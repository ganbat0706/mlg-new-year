# Phase 2 — Гурван шинэ тоглоом, баярын төрх, шинэ урилга

**Огноо:** 2026-11-19
**Өмнөх:** `2026-11-18-mlg-new-year-game-design.md` (17 task, бүгд дууссан)

## 1. Юунаас үүдсэн

Хэрэглэгч бүтээгдсэн системийг туршаад дөрвөн зүйл хүссэн:

1. Урилга хэт загварлаг харагдаж байна — гоё болгох
2. Логистикийн сэдэвтэй ачаалалтын заагч (loader) нэмэх
3. Шинэ жилийн уур амьсгал нэмэх, анимэйшн сайжруулах
4. «Ачаа ачих» тоглоом уйтгартай — 2-3 шинэ тоглоомоор солих

Хэрэглэгчийн шийдвэр: **гурван тоглоомыг бүгдийг нь дараалан** тоглоно.
Баярын төрх **дунд зэрэг** — одоогийн цэвэр бүтцийг алдахгүй.

## 2. Онооны шинэ тэнцвэр

| Үе шат | Оноо | Хугацаа |
|---|---|---|
| Асуулт (10 ширхэг) | 2,000 | ~100 сек |
| 1. Зөв зам | ~960 | 15 сек |
| 2. Контейнер овоолох | ~960 | 10 сек |
| 3. Хос манифест | ~960 | 20 сек |
| **Нийт** | **~4,880** | **~2.4 мин** |

Мэдлэг 41%, ур чадвар 59%. Гурван оролдлого ≈ 7.5 минут.

**Шийдвэрийн үндэслэл:** хэрэглэгч гурвууланг тоглохыг сонгосон. Хэрэв
тоглоом бүрийг 1,880 (одоогийн reaction-ийн оноо) болговол асуулт 26%
болж унаж, мэдлэг бараг хамаагүй болно. Тоглоом бүрийг ~960 болгосноор
мэдлэг утга учиртай хэвээр үлдэнэ.

## 3. Гурван тоглоомын дизайн

Бүгд ижил зарчмаар ажиллана — **серверийн бүхэл тоон seed → хуваарь →
browser тоглоно → үйлдлийн жагсаалт буцна → сервер хуваарийг дахин
үүсгэж тоглолтыг давтан шалгана.** Browser-ийн оноонд хэзээ ч итгэхгүй.

Тоглоом бүр `mulberry32(seed ^ <тогтмол>)` -ээр өөрийн санамсаргүй
урсгалтай болно — нэг seed-ээс гурван өөр хуваарь гарна.

### 3.1 Зөв зам (`sort`)

- Дэлгэцийн голд нэг контейнер: том дүрс + үг (төмөр зам / авто / агаар),
  эсвэл «Эвдэрсэн»
- Доод талд 4 тогтмол товч: **Төмөр зам · Авто · Агаар · Буцаах**
- Дарвал дараагийнх шууд гарна

**Хуваарь:** `[{ id, mode, damaged }]` — 12 ширхэг, 20% нь эвдэрсэн
**Browser буцаана:** `[{ id, lane, t }]`
**Сервер шалгана:**
- `id` нь 0,1,2… дараалсан байх
- `t` чанд өсөх, ≤ 15,400 мс
- **хоёр даралтын зай ≥ 200 мс** (хүн үүнээс хурдан дарж чадахгүй)
- Хүлээгдэх зам = `damaged ? 'return' : mode`
- Зөв **+80**, буруу **−40**, нийлбэрийг эцэст нь 0-д clamp

**Дээд оноо:** 12 × 80 = **960**

### 3.2 Контейнер овоолох (`stack`)

- Контейнер кранаас баруун зүүн савлана (гурвалжин долгион, 10-90%)
- «Буулгах» дарахад доошилно (500 мс)
- Овоолгын төвөөс ±12% дотор бол суулаа, эс бөгөөс унана (0 оноо)
- Дараагийн түвшин арай хурдан савлана

**Хуваарь:** seed → түвшин бүрийн эхлэх тал ба фаз.
Байрлал нь цагийн **цэвэр функц**: `P_n = 1600 − 60n` мс
**Browser буцаана:** `[{ level, t }]`
**Сервер шалгана:**
- Түвшин 1 нь 0-д нээгдэнэ, `n+1` нь `t_n + 500`-д
- Дараалалгүй эсвэл эрт ирсэн үйлдлийг татгалзана
- `offset = x(t − open_n) − centre_{n−1}`, `centre_0 = 50`
- `|offset| ≤ 12` → суусан, `centre_n = x`,
  оноо = `100 + round(60 × (1 − |offset|/12))`
- Эс бөгөөс 0, төв өөрчлөгдөхгүй

**Дээд оноо:** 6 түвшин × 160 = **960**

### 3.3 Хос манифест (`memo`)

- 3×4 = 12 хаалттай контейнер, 6 хос
- Дарвал нээгдэж дүрс + үг гарна (морь, хадаг, бууз, онгоц, хөлөг, вагон)
- Хоёр ижил → нээлттэй үлдэнэ; өөр → 600 мс дараа хаагдана
- Эрт дуусгавал цагийн урамшуулал

**Хуваарь:** seed → холисон байрлал
**Browser буцаана:** `[{ card, t }]`
**Сервер шалгана:** ижил төлөвт машиныг давтан ажиллуулна. Нээлттэй
эсвэл тохирсон хөзөр дээрх даралт, 600 мс түгжээний доторх даралтыг
**татгалзахгүй, ЗҮГЭЭР ЛЕ АЛГАСНА** — client болон сервер нэг төлөвт
үлдэх ёстой. Даралтын зай ≥ 200 мс.
- Хос бүр **+130**
- Урамшуулал = `floor((20,000 − t_дуусав) / 1000) × 30`, дээд тал нь 180

**Дээд оноо:** 6 × 130 + 180 = **960**

### 3.4 Нийтлэг хамгаалалт — шинэ

Fable кодыг уншаад одоогийн тоглоомын **жинхэнэ сул талыг** олов:
серверээс ирэх хуваарьт объектын төрөл (сайн/муу) бичигдсэн байдаг тул
скрипт бичсэн хүн зөвхөн сайныг нь төгс тохироотой дарж дээд оноог
баталгаатай авч чадна. Хуваарийг browser-т илгээхгүй байх боломжгүй —
зурахын тулд хэрэгтэй.

**Шийдэл:** бүх тоглоомд **хамгийн бага үйлдлийн зай 200 мс**
шалгана. Хүний хуруу үүнээс хурдан дарж чадахгүй. Зөрчсөн үйлдлийг
алгасна, мөн оролдлогыг `flagged` гэж тэмдэглэнэ (админд харагдана,
шагнал өгөхөөс өмнө шалгах боломжтой).

Мөн `memo` тоглоомд **алдаагүй дууссан** тоглолтыг тэмдэглэнэ —
жинхэнээр 10,000-д 1 удаа тохиолддог.

## 4. Өгөгдлийн сангийн өөрчлөлт

`attempts` хүснэгтэд:

```
sortScore    int  not null default 0
stackScore   int  not null default 0
memoScore    int  not null default 0
sortDone     bool not null default false
stackDone    bool not null default false
memoDone     bool not null default false
flagged      bool not null default false
flagReason   text
```

`reactionScore` / `reactionDone` хасагдана.

`totalScore = quizScore + sortScore + stackScore + memoScore`

## 5. API

| Route | Юу хийх |
|---|---|
| `POST /api/attempt/[id]/game/sort` | Зөв замын үйлдлүүдийг шалгаж оноо тооцно |
| `POST /api/attempt/[id]/game/stack` | Овоолох |
| `POST /api/attempt/[id]/game/memo` | Хос манифест |

`startAttempt` нь гурван хуваарийг бүгдийг нь буцаана.
Тоглоом бүр **нэг л удаа** илгээгдэнэ (`*Done` тугаар).

## 6. Баярын төрх ба анимэйшн

Fable-ийн урлагийн чиглэлээр (тусдаа баримт). Хязгаарлалт:

- Утас эхэнд, 360px-ээс дээш
- Дунд зэргийн Android, мобайл дата — хүнд сан байхгүй, WebGL байхгүй,
  видео байхгүй. Зөвхөн CSS анимэйшн ба жижиг inline SVG
- Тоглоомын үед `requestAnimationFrame` гүйж байгаа тул **түүнтэй
  өрсөлдөх зүйл байх ёсгүй**
- `prefers-reduced-motion: reduce` заавал хүндэтгэнэ
- Контраст AA хэвээр, брэндийн улаан тэргүүлнэ
- Цайвар сэдэв хэвээр — бараан сэдэв нэмэхгүй

## 9. Шийдвэрүүд (2026-11-19, шөнө)

### 9.1 Урилгын чиглэл — **C «Чингэлэг»** (хэрэглэгч сонгов, 2026-11-19)

Fable гурван чиглэл гаргав (canvas:
https://claude.ai/artifact/Cnzb8g1KjNy69TzwuPoC2F):

- **A · Ачааны баримт** — урилга нь ачааны бичиг баримт болно. Хүлээн
  авагч = зочин, «АЧАА: Баяр хөөр, 1 ш», эргүүлсэн улаан гаалийн тамга,
  манифест хүснэгт, кодын хажууд баркод, үүдэнд үзүүлэх улаан таслах хэсэг
- **B · Шөнийн зам** — харанхуй өвлийн шөнө, цас, холын дулаан гэрэл рүү
  явж буй ачааны машин. Fable өөрөө үүнийг санал болгов
- **C · Чингэлэг** — бүтэн карт нь улаан контейнерийн хаалга

**Анхны шийдвэр (шөнө, рендер харалгүй): A.** Гурвуулангийн РЕНДЕРИЙГ
ХАРААГҮЙ, зөвхөн тайлбараар сонгосон тул энэ нь түр шийдвэр байв.

**Эцсийн шийдвэр: C «Чингэлэг» — хэрэглэгч өөрөө сонгов** («Fable
урилгийн template-ийн C хувилбарыг ашигла»). `image/route.tsx` бүтнээрээ
C рүү шилжив.

C-д юу байгаа вэ: бүтэн хуудас нь брэндийн улаан чингэлэгийн хаалга —
18 давталттай хажуугийн атираа, хоёр талын цоожны хошуу, хошууны
хавчаар ба бариул, дээврийн ирмэг дэх цасан давхарга, стенсил маягийн
118px гарчиг, морин жилийн хар тэмдэг, урилгын код нь чингэлэгийн
дугаарын байрлалд цагаан ялтас дээр.

**C-гийн гол эрсдэл — контраст.** Бүтэн дүүрэн `#ED1C24` дэвсгэр дээр
цагаан бичвэр ердөө 4.38:1 — энэ нь ЗӨВХӨН том бичвэрт (≥24px энгийн,
≥19px bold) WCAG AA-д тэнцдэг. Тиймээс 18px стенсил шошго бүрийг хар
(`#221E20`) эсвэл цагаан ялтас дээр байрлуулав; улаан дээр үлдсэн
бичвэрүүд бүгд 22px bold-оос дээш.

**Бодит рендерээр илэрсэн, засагдсан хоёр алдаа** (таамаглаар биш,
1080×1350 PNG дээр пиксел хэмжиж олов):

1. Хаалганы бариул 70px урт байсан нь контентын багана (x=110) руу 4px
   орж, ЭЗЭМШИГЧийн нэрний эхний үсэгт хүрч байв → 46px болгов.
2. 192 тэмдэгттэй байршил гурав дахь мөрөндөө «…буудлын Их» гэж ҮГНИЙ
   ДУНДУУР тасарч байв → `fitVenue()` нэмэв: фонт бүрийн тэмдэгтийн
   төсвийг бодит хэмжилтээс (≈609/фонт тэмдэгт/мөр) гаргаж, үгийн зааг
   дээр таслаад гурван цэг тавина. Байршлын талбар тогтмол 96px өндөр
   тул ДУГААРын ялтас хэзээ ч доошоо түлхэгдэхгүй.

Үүний үр дүнд C дээр байршлын хязгаар A-гаас СУЛАРСАН: ~150 тэмдэгт
хүртэл бүтнээрээ багтана (A дээр ~60 байсан).

### 9.2 Баярын чиглэл — Цагаан сарын тэмдэг ХЭРЭГЛЭХГҮЙ

Fable чухал соёлын залруулга хийв: хадаг, улзий хээ, морин жилийн дүрс
нь **Цагаан сарынх** (2 сар). 12 сарын оффисын шинэ жил бол **өвлийн
баяр** — цас, гацуур, ачааны машин. Эдгээрийг хольвол буруу баярын
тэмдэг болно. Улаан-ногоон Christmas мөн зээлсэн.

Сонгосон: **өвөл + брэндийн улаан + алхан хээний нэг зурвас**.
Дэлгэрэнгүй: `docs/design/2026-11-19-art-direction.md`

### 9.3 Fable ашиглалтын хязгаар

Хэрэглэгч 30%-иас хэтрүүлэхгүй гэж заав. Одоогоор 2%. Бүх бүтээлч
оролт (3 урилга, 3 тоглоом, урлагийн чиглэл) цугларсан тул цаашид
Fable дуудахгүй — хэрэгжүүлэлт энгийн загвараар.

### 9.4 Бүтээгдэхүүний цоорхой — оноо буух мөч

Fable илрүүлэв: `PlayClient` нь `finish`-ийн хариуг хаядаг, `/result`
шууд leaderboard-оор нээгддэг — **тоглогч оноогоо хэзээ ч тэмдэглэн
хардаггүй**. Шагналын мөч огт байхгүй. Phase 2-т засна.
